# 02. Folder map

A grown-up layout. Start smaller; add folders when you feel the need.

```
YOUR-NAME/
  CLAUDE.md            the brain: rules, routing, pointers (see 04)
  AGENTS.md            "read CLAUDE.md" (for Codex)
  about-me.md          who you are, how you work, what you want help with
  todo.md              open work only (see 08)
  done.md              finished work, append-only
  journal.md           the AI's work log: what it built and why
  activity-log.md      what ran on its own (watchers, routines)
  team-inbox/          raw drops: voice memos, transcripts, photos
  owners-inbox/_New/   AI output waiting for your review
  people/              one file per person (see 03)
  courses/             one file per course you teach or take
  projects/            one file per project
  topics/              everything else worth a page
  team/                your AI specialists (see 05)
  SOPs/                procedures (see 09)
  knowledge/           finished, approved material you reuse
  past-work/           archive, plus failure-journal.md
  tools/               scripts the AI wrote for you
```

## The filing rule

Before saving anything new, ask: does this file belong to exactly one thing that already has a home?

- Yes: file it there. A handout for week 3 goes in that course's week 3 folder. A photo of a person goes in `people/attachments/`.
- No, or not sure: `owners-inbox/_New/`. You move it later.

Never let the AI invent new destinations. Unsure always means `_New/`.

## Two kinds of files

- Graph files (people, courses, topics): can use Obsidian extras like `[[links]]` and tags.
- Deliverables (handouts, letters, slides): plain and clean. No tags, no AI clutter.
