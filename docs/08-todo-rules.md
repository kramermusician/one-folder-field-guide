# 08. To-do rules that stay honest

A to-do list rots when finished items pile up and old ones never get decided. Rules that fix that:

1. `todo.md` holds open work only. Done items move to `done.md` with the date.
2. Never delete. Dropping moves the item to a Dropped section with a reason.
3. Three tiers: P1 this week (max 7), P2 this month, P3 someday.
4. Each item says what done looks like and the next step. One line.
5. Stamp dates: `<!--added:2026-11-17-->`. The AI can then flag stale items (P1 after 2 weeks, P2 after 6, P3 after 3 months) and ask you: keep, snooze, demote or drop.
6. Every project gets a "Done when I can..." sentence before work starts. New ideas mid-build go to a v2 list.

Ask the AI "what should I work on?" and it answers with P1s only.
